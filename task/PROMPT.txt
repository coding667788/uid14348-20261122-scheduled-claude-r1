实现网络安全控制面的离线模型，用来检查多区域服务代理在灰度发布中是否始终保持租户隔离。在输入中声明节点、链路、调用身份、服务和两套授权策略。全部为合成拓扑，只传播无载荷的抽象身份标记。单个代理可以同时持有不同版本的出站标记映射和入站校验规则，每次允许的转发都由明确的身份、目标服务、策略版本与租户标签匹配决定；报文经过代理后可以按获批映射更换标记，但其原始租户在模型中不变。可将各段已登记的链路投递和转发延迟视为离散步数，走过环路的在途标记仍随 TTL 降低，期限耗尽即丢弃。网络策略的安全性按最终交给服务时的原始租户和服务标签核对。必达性按请求录入时的适用名单与截止步校验，每个获准请求至少有一条合法投递；同一请求经过不同分支不能相互覆盖或混写回执。

升级动作含安装入站新版、切换出口映射、撤下旧版规则、插入带代次的排空屏障、暂停及恢复指定代理。暂停期间代理不接受或转发新标记，已入队标记只等待或到期。安装仅让指定代理多接受新版，不改原发射标记。撤下旧版本前须有受影响路径的真实排空证明：所有可能仍处在可到达该代理的旧标记都已交付或丢弃，屏障完成后新事件不能重新注入已关闭代次。输入还给出链路故障域和至多一个故障域的失效/恢复窗口，恢复后的链路按输入伸缩时限，不得把已丢弃或已到期的标记当作恢复成功。replay 读取给定时序，输出每一屏障的见证与最早违规前缀。晚到、重复及与当前代次不符的交付，各自留下可核验原因。

plan 根据批准动作的先后约束与时间槽，选择对全部输入允许的链路延迟和单域故障情形都安全且满足必达性的固定发布表。计划不得依赖运行时才能观察到的未来延迟；排空动作可选择一个等待槽并在槽末检查。不允许避开某一情形靠换一份计划。按停用代理总时长、发布步数与动作 ID 序列最小化。若没有合法表，对输入附带的基线顺序报告最早的排程约束冲突；基线符合排程约束时，给最短的隔离或必达失败前缀，等长取事件 ID 序列最小者。支持 14 个代理、16 个动作、10 个时间槽，TTL 至多 6；说明如何按仍影响未来的在途状态压缩时间线。覆盖两个最终合法版本之间存在泄露窗口、入口更换导致旧标记滞留、同一状态在不同屏障代次有不同未来、故障窗口结束恰逢 TTL、单情形最短序列无法共同使用、以及最优计划的小拓扑穷举对拍。

交付一套从空仓库实现的 Windows 原生 Python 3.12 程序，仅使用标准库和 CPU。用 python -m solution <命令> CASE.json 计算，stdout 返回确定性 UTF-8 JSON，结构异常提供字段位置与错误码。随代码附用虚构拓扑可直接运行的样例、写全输入输出及复现步骤的 README、以及用 python -m unittest discover -s tests -v 运行的断言测试。
